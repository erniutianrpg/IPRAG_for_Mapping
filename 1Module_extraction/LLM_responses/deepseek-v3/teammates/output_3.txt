Here are the distinct architecture modules extracted from the documentation, along with their responsibilities:  

**module name:** UI (Frontend)  
**module description:** Handles user interactions and renders the single-page application built with Angular. Consists of HTML, CSS, and TypeScript files, which are compiled into browser-ready assets. Processes user-invoked requests, including initial page loads and subsequent AJAX calls.  

**module name:** UI Server (Backend Controllers)  
**module description:** Acts as the entry point for backend logic via RESTful controllers. Processes HTTP requests through servlets (WebPageServlet, WebApiServlet) and applies filters (e.g., CSRF checks). Delegates business logic to the Logic component and returns results (e.g., JSON, file downloads).  

**module name:** Logic  
**module description:** Manages core business logic, including entity relationships, transactions, input sanitization, and access control. Provides a facade (Logic class) to coordinate operations across subsystems (e.g., GateKeeper for authorization, EmailSender for notifications). Handles cascade operations and integrates with GAE APIs (e.g., task queues).  

**module name:** Storage  
**module description:** Performs CRUD operations on data entities using GAE Datastore (NoSQL). Validates entity state, abstracts datastore complexities, and returns data transfer objects (Attributes classes). Excludes cascade logic, which is handled by the Logic component. Includes search/indexing functionality.  

**module name:** Common  
**module description:** Provides shared utilities across the application, including helper classes (common.util), custom exceptions (common.exceptions), and data transfer objects (common.datatransfer) for inter-component communication.  

**module name:** Test Driver  
**module description:** Facilitates automated testing with TestNG (Java) and Jest (JavaScript). Includes unit, integration, and system tests (e.g., webapi, automated actions). Uses JSON for test data and HttpUnit/Selenium for simulated or browser-based testing.  

**module name:** E2E (End-to-End Testing)  
**module description:** Conducts system-wide tests via Selenium (browser automation) and REST API calls. Includes page object abstractions (e2e.pageobjects) and load/performance testing (experimental).  

**module name:** Client  
**module description:** Enables direct backend access for administrative tasks (e.g., data migration, statistics) via scripts. Uses remote API calls, bypassing the UI.  

**module name:** Automated Services  
**module description:** Handles GAE-triggered requests (cron jobs, task queues) for scheduled tasks (e.g., feedback reminders). Validates administrator privileges and executes actions via AutomatedServlet.  

*(Note: Semantically similar modules like "UI Browser" and "UI" were merged under "UI (Frontend)," while "Automated Requests" and "Task Queue Workers" were consolidated into "Automated Services.")*
