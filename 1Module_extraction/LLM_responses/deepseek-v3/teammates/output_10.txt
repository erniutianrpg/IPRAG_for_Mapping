Here are the distinct architecture modules extracted from the documentation, along with their responsibilities:

module name: UI (Frontend), module description: Handles user interactions and renders the single-page application built with Angular, consisting of HTML, CSS, and JavaScript/TypeScript. Processes user-invoked requests and manages client-side logic like input validation and sorting.

module name: UI Server (Backend), module description: Acts as the entry point for backend logic via REST-ful controllers. Processes HTTP requests, applies filters (e.g., CSRF checks), and routes requests to appropriate servlets (WebPageServlet for initial page loads, WebApiServlet for AJAX requests).

module name: Logic, module description: Manages core business logic, including entity relationships, transactions, input sanitization, access control checks, and integration with external APIs (e.g., email services, task queues). Comprises logic.api (facade for UI interactions) and logic.core (core business rules).

module name: Storage, module description: Performs CRUD operations on data entities using GAE Datastore (NoSQL). Validates entity data, abstracts datastore complexities, and provides data transfer objects (Attributes classes) to other components. Includes storage.api (interface for Logic), storage.entity (persistable entities), and storage.search (search functionality).

module name: Common, module description: Provides shared utilities across the application, including helper classes (common.util), custom exceptions (common.exceptions), and data transfer objects (common.datatransfer) used for inter-component communication.

module name: Test Driver, module description: Facilitates automated regression testing with TestNG (Java) and Jest (JavaScript). Includes test.driver (testing infrastructure) and test.cases (unit/integration tests for all components). Uses JSON for test data and HttpUnit for servlet-level testing.

module name: E2E (End-to-End), module description: Conducts system-level testing via Selenium (browser automation) and REST API calls. Includes e2e.pageobjects (UI abstractions), e2e.cases (test scenarios), and experimental load/performance tests (x.lnp).

module name: Client, module description: Provides administrative scripts for direct backend access (e.g., data migration, statistics). Includes client.remoteapi (backend connectivity) and client.scripts (task implementations).

module name: Automated Processing, module description: Handles GAE server-invoked requests (cron jobs/task queues) via AutomatedServlet, performing scheduled tasks like feedback reminders. Enforces admin privileges and uses AutomatedAction classes for task execution.
