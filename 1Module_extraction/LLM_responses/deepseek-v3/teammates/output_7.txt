Here are the distinct architecture modules extracted from the documentation, along with their responsibilities:

module name: UI (Frontend), module description: Handles user interactions and renders the single-page application built with Angular, consisting of HTML, CSS, and JavaScript/TypeScript. Processes user-invoked requests and serves static assets.  

module name: UI Server (Backend), module description: Acts as the entry point for backend logic via REST-ful controllers. Processes HTTP requests, applies filters (e.g., CSRF checks), and routes requests to appropriate servlets (WebPageServlet for initial page loads, WebApiServlet for AJAX requests).  

module name: Logic, module description: Manages core business logic, including entity relationships, transactions, input sanitization, access control, and integration with external APIs (e.g., email services, GAE task queues). Exposes functionality via a Facade class (Logic) and subcomponents like GateKeeper (access control) and EmailSender.  

module name: Storage, module description: Performs CRUD operations on data entities using GAE Datastore (NoSQL). Validates entity state, abstracts datastore complexities, and returns data via transfer objects (Attributes classes). Contains minimal logic beyond persistence.  

module name: Common, module description: Provides shared utilities across the application, including helper classes, custom exceptions (common.exceptions), and data transfer objects (common.datatransfer) for inter-component communication.  

module name: Test Driver, module description: Facilitates automated testing with TestNG (Java) and Jest (JavaScript). Includes infrastructure for unit, integration, and system tests (e.g., HttpUnit for servlet-level tests, Selenium for E2E). Organizes tests by component (logic, storage, etc.).  

module name: E2E (End-to-End), module description: Conducts system-level tests interacting with the application as a whole via browsers (Selenium) or REST APIs. Includes load/performance testing (experimental) and page object abstractions for UI testing.  

module name: Client, module description: Enables direct backend access for administrative tasks (e.g., data migration, statistics) via scripts, bypassing the UI. Uses remote API utilities to interact with the server.  

module name: Automated Services, module description: Handles GAE-invoked requests (cron jobs, task queues) for scheduled tasks (e.g., feedback reminders). Executes via AutomatedServlet with privileged access checks.  

(Note: Semantically similar modules like "UI Browser" and "ui.website" were merged into "UI (Frontend)"; "Web API" and "REST-ful controller" were consolidated under "UI Server (Backend)"; "TaskQueuer" and "AutomatedAction" were grouped into "Automated Services.")
