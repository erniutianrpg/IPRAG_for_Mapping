Here are the distinct architecture modules extracted from the documentation, along with their responsibilities:

module name: UI (Frontend), module description: Handles user interactions and renders the single-page application built with Angular, consisting of HTML, CSS, and JavaScript/TypeScript. Processes user-invoked requests and serves static assets.

module name: UI Server (Backend), module description: Acts as the entry point for backend logic via REST-ful controllers. Processes HTTP requests, applies filters (e.g., CSRF checks), and routes requests to appropriate servlets (WebPageServlet for initial page load, WebApiServlet for AJAX requests).

module name: Logic, module description: Manages core business logic, including entity relationships, transactions, input sanitization, access control checks, and integration with external APIs (e.g., email services, task queues). Comprises logic.api (facade for UI interactions) and logic.core (core business rules).

module name: Storage, module description: Performs CRUD operations on data entities using GAE Datastore (NoSQL). Validates entity data, abstracts datastore complexities, and provides data transfer objects (Attributes classes) to other components. Includes storage.api (interface for Logic), storage.entity (persistable entities), and storage.search (search functionality).

module name: Common, module description: Provides shared utilities across the application, including helper classes (common.util), custom exceptions (common.exceptions), and data transfer objects (common.datatransfer) for inter-component communication.

module name: Test Driver, module description: Automates regression testing with TestNG (Java) and Jest (JavaScript). Includes infrastructure for component tests (logic, storage, etc.) and system tests (user-invoked/automated actions). Uses JSON for test data and HttpUnit for servlet-level testing.

module name: E2E (End-to-End), module description: Conducts system-level tests interacting with the application as a whole via browsers (Selenium) or REST API calls. Includes page object abstractions, test cases, and experimental load/performance tests.

module name: Client, module description: Provides administrative scripts for direct backend access (e.g., data migration, statistics). Uses client.remoteapi to bypass the UI and interact with the backend.

module name: Automated Services, module description: Handles GAE-invoked requests (cron jobs, task queues) for scheduled tasks (e.g., feedback reminders). Processes these via AutomatedServlet and enforces admin privileges.

module name: Security Layer, module description: Implements access control (origin checks, authentication/authorization) for Web API requests, including CSRF protection and privilege verification via GateKeeper.
