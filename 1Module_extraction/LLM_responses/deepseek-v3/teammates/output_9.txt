Here are the distinct architecture modules extracted from the documentation, along with their responsibilities:

module name: UI (Frontend), module description: Handles user interactions and renders the single-page application built with Angular, consisting of HTML, CSS, and JavaScript/TypeScript. Processes user-invoked requests (e.g., page navigation, AJAX calls) and communicates with the backend via RESTful APIs.

module name: UI Server (Backend), module description: Serves as the entry point for backend logic, processing HTTP requests via RESTful controllers (e.g., WebPageServlet, WebApiServlet). Manages request routing, access control (CSRF, authentication/authorization), and delegates business logic to the Logic component.

module name: Logic, module description: Implements core business logic, including entity relationship management, transaction handling, input sanitization, and access control checks. Acts as a facade (via the `Logic` class) to coordinate operations across GateKeeper (access control), EmailGenerator/EmailSender (email services), and TaskQueuer (task scheduling).

module name: Storage, module description: Performs CRUD operations on data entities using GAE Datastore (NoSQL). Validates entity state, abstracts datastore complexities (e.g., GQL queries), and returns data via DTOs (Attributes classes). Contains minimal logic beyond direct persistence operations.

module name: Common, module description: Provides shared utilities across the application, including helper classes (common.util), custom exceptions (common.exceptions), and data transfer objects (common.datatransfer) like Attributes for inter-component communication.

module name: Test Driver, module description: Facilitates automated testing with TestNG (Java), Jest (JavaScript), and HttpUnit (servlet-level tests). Includes infrastructure for component/integration tests (e.g., logic, storage) and system tests (e.g., webapi, automated actions).

module name: E2E (End-to-End), module description: Conducts system-level tests via Selenium (browser automation) and REST API calls. Includes page object abstractions (e2e.pageobjects) and supports Load & Performance (L&P) testing.

module name: Client, module description: Enables direct backend access for administrative tasks (e.g., data migration, statistics) via scripts, bypassing the UI. Uses remote API utilities (client.remoteapi) to interact with the backend.

module name: Automated Services, module description: Handles GAE server-invoked requests (cron jobs, task queues) for scheduled tasks (e.g., feedback reminders). Processes these via AutomatedServlet and enforces admin privileges.
