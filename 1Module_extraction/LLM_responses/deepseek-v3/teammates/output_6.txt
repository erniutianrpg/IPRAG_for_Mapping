Here are the distinct architecture modules extracted from the documentation, along with their responsibilities:

module name: UI (Frontend),  
module description: Handles user interactions and renders the single-page application built with Angular, consisting of HTML, CSS, and TypeScript. Processes user-invoked requests (e.g., page navigation, AJAX calls) and communicates with the backend via RESTful APIs.  

module name: UI Server (Backend),  
module description: Acts as the entry point for backend logic, serving RESTful APIs via WebApiServlet and WebPageServlet. Processes user-invoked and automated requests, enforces access control (CSRF, authentication), and delegates actions to the Logic component.  

module name: Logic,  
module description: Manages core business logic, including entity relationships, transactions, input sanitization, and access control. Provides APIs for CRUD operations, email generation/sending, and task queuing. Comprises logic.api (facade) and logic.core (implementation).  

module name: Storage,  
module description: Performs CRUD operations on GAE Datastore (NoSQL), validates entity data, and abstracts datastore complexities. Contains storage.api (interfaces), storage.entity (persistable objects), and storage.search (search/indexing). Returns data via DTOs (Attributes classes).  

module name: Common,  
module description: Provides shared utilities across the application, including helper classes (common.util), custom exceptions (common.exceptions), and data transfer objects (common.datatransfer) for inter-component communication.  

module name: Test Driver,  
module description: Automates regression testing with TestNG (Java) and Jest (JavaScript). Includes test.driver (infrastructure) and test.cases (unit/integration tests). Covers component tests (e.g., logic, storage) and system tests (e.g., Web API, automated actions).  

module name: E2E (End-to-End),  
module description: Conducts system-level tests via Selenium (browser automation) and REST API calls. Includes e2e.pageobjects (UI abstractions), e2e.cases (test scenarios), and experimental load/performance tests (x.lnp).  

module name: Client,  
module description: Enables direct backend access for administrative tasks (e.g., data migration, statistics) via scripts. Comprises client.remoteapi (backend connectivity) and client.scripts (task implementations).  

module name: Automated Services,  
module description: Handles GAE-triggered requests (cron jobs, task queues) via AutomatedServlet, executing scheduled tasks (e.g., feedback reminders) with administrator privileges. Configured via cron.xml and queue.xml.  

(Note: Semantically similar modules like "UI Browser" and "UI component" were merged into "UI (Frontend)"; "AutomatedServlet" and related logic were grouped under "Automated Services.")
