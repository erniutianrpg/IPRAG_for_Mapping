Here are the distinct architecture modules extracted from the documentation, along with their responsibilities:

module name: UI (Frontend), module description: Handles user interactions and renders the single-page application built with Angular, consisting of HTML, CSS, and JavaScript/TypeScript. Processes user-invoked requests and serves static assets.

module name: UI Server (Backend), module description: Acts as the entry point for backend logic via REST-ful controllers. Processes HTTP requests, applies filters (e.g., CSRF checks), and routes requests to appropriate servlets (WebPageServlet for initial page loads, WebApiServlet for AJAX requests).

module name: Logic, module description: Manages core business logic, including entity relationships, transactions, input sanitization, access control checks, and integration with external APIs (email services, task queues). Provides facade classes (Logic, GateKeeper, EmailGenerator, etc.) for UI interaction.

module name: Storage, module description: Performs CRUD operations on data entities using GAE Datastore. Validates entity data, abstracts datastore complexities, and provides data transfer objects (Attributes classes). Contains minimal business logic beyond direct persistence operations.

module name: Common, module description: Provides shared utilities across the application, including helper classes, custom exceptions, and data transfer objects (e.g., CourseAttributes). Serves as a cross-cutting concerns module.

module name: Test Driver, module description: Facilitates automated testing with TestNG (Java) and Jest (JavaScript). Includes infrastructure for unit, integration, and system tests (e.g., HttpUnit for servlet-level tests, Selenium for E2E).

module name: E2E (End-to-End), module description: Performs system-wide testing via browser automation (Selenium) or REST API calls. Includes load/performance testing capabilities and page object abstractions.

module name: Client, module description: Enables direct backend access for administrative tasks (e.g., data migration, statistics) via scripts, bypassing the UI. Uses remote API utilities.

module name: Automated Processing, module description: Handles GAE-invoked requests (cron jobs, task queues) for scheduled or long-running tasks. Includes privilege checks and specialized action classes (AutomatedAction).
