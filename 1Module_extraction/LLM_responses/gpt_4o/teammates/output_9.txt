1. **UI Component**: The UI component functions as the client-side interface of the TEAMMATES application. It is built using the Angular framework and consists of HTML, SCSS, and TypeScript files which are compiled into HTML, CSS, and JavaScript for interactions within a web browser. Its responsibilities include rendering web pages and handling client-side interactions like sorting and input validation, utilizing AJAX for data requests from the server.

2. **UI Server**: This is the server-side entry point for managing user interactions and back-end logic, involving a REST-ful controller. It processes user-invoked requests, applying custom filters, and then forwarding to servlet objects like `WebPageServlet` and `WebApiServlet` to handle web pages and API requests respectively.

3. **Logic Component**: Responsible for executing the business logic of the application. It manages tasks such as entity relationships, transactions, input sanitization, access control checks, and interactions with APIs for additional functionalities like email sending and task queue management. It serves as the intermediary between the UI component and the Storage component.

4. **Storage Component**: Handles data persistence and performs CRUD operations on data entities using GAE Datastore. It validates data, manages GQL queries, and ensures isolation from storage complexities for the Logic component. It does not perform cascade operations, relying on the Logic component to handle those.

5. **Common Component**: Provides utility functions, custom exceptions, and data transfer objects used throughout the application. Its data transfer classes are lightweight objects facilitating structured data transfer between other components.

6. **Test Driver**: Facilitates automated regression testing across TEAMMATES using frameworks such as TestNG, Jest, and Selenium. It sets up environments for testing components in isolation or integration, as well as conducting end-to-end testing without requiring an actual web server.

7. **E2E Component**: Focuses on end-to-end and load & performance testing. It simulates interactions with the application as a user would, using real web browsers, or through REST API calls for back-end logic testing.

8. **Client Component**: This module allows direct interaction with the back-end for administrative tasks such as data migration and statistics calculation. It comprises scripts and remote API classes necessary for these operations.
