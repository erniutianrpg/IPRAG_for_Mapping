module name: Model  
module description: The Model module represents the most important data structures, such as BibDatases, BibEntries, Events, and related aspects. It is central to the architecture and contains minimal logic, focused on maintaining the integrity of data structures. The Model should have no dependencies on other classes in the application.

module name: Logic  
module description: The Logic module is responsible for data manipulation tasks, including reading, writing, importing, exporting, and modifying the data structure within the Model. It serves as an API for the GUI to interact with and should only depend on the Model classes.

module name: GUI  
module description: The GUI module is the user interface layer that handles interactions with the user, including preferences and task-solving assistance. It is the outer shell of the architecture, designed to interface with the intermediate Logic layer.

module name: CLI  
module description: The CLI module bundles the classes responsible for the application's command line interface, facilitating activities performed via command line inputs.

module name: Preferences  
module description: The Preferences module manages all information that is customizable by a user according to their personal needs, typically reflecting user-specific configurations and settings.

module name: Utility  
module description: The Utility module encompasses packages that provide auxiliary functions and support to other modules, often focused on general-purpose functionalities that enhance the overall system architecture.

module name: Event Bus  
module description: The Event Bus module allows publishing of events from the Model to other layers, enabling those layers to react to changes in the core while maintaining a structured architecture.
