# mediastore / Packaging
## 模块职责
作为mediastore系统的音频打包服务模块，分为基础支撑层与业务实现层：提供整个模块的基础能力支撑、规范约定，同时对外暴露可本地/远程调用的标准化音频打包服务，配套提供音频转码、下载缓存、Web端用户交互的支撑能力，支撑音频打包全流程与EJB打包部署。
## 核心功能
1. 基础支撑能力：提供EJB开发统一基类，兼容本地/远程EJB调用；支持XML配置加载、properties常量读取与部署配置生成，支持配置热更新；定义可序列化统一核心数据结构；构建分层自定义异常体系；约定核心业务与依赖功能的接口契约
2. 音频打包能力：同时支持EJB本地/远程调用，可将多个音频打包为ZIP压缩包，单音频默认输出MP3格式，集成LAME实现音频转码
3. 音频下载缓存：基于Guava Cache实现全局单例缓存，提供缓存命中查询、写入与维护能力，减少重复下载提升性能
4. 底层工具支撑：提供文件IO与临时文件管理、EJB JNDI查找配置、LAME音频编码、Web会话管理四类工具，支撑全流程处理
5. Web交互支撑：提供用户注册请求处理、登录会话状态检查能力，支撑Web端用户接入
## 主要代码区域
1. 基础支撑层：
   - 根基础类：`BaseEJB`（所有EJB的公共抽象基类）
   - 配置层：EJB配置加载、全局常量读取、配置数据模型、配置生成入口`Main`
   - 数据层：音频、用户相关可序列化业务数据结构，区分本地/远端文件
   - 异常层：分层自定义异常体系
   - 接口约定层：核心打包接口`IPackaging`、各依赖功能的本地/远程接口契约
2. 业务实现层：
   - 对外服务接口：`IPackagingLocal`（本地调用入口）、`IPackagingRemote`（远程调用入口）
   - 核心业务实现：`PackagingImpl`（打包逻辑）、`CacheImpl`/`CacheSingleton`（缓存逻辑）
   - 工具层：`FSUtil`（文件系统）、`JNDIUtil`/`PropertiesUtil`（JNDI配置查找）、`LameUtil`（音频编码）、`SessionUtil`（Web会话）
   - 扩展数据结构：`IdAndBitrate`（缓存复合键）
   - Web层：`RegisterBean`（用户注册JSF处理）
## 与其他模块的交互
1. 内部依赖：为Packaging模块自身业务实现层提供数据结构、接口规范、基础能力支撑，是打包业务与部署的基础依赖；打包核心实现依赖本模块工具层能力，缓存组件依赖本模块的Guava Cache实现与缓存键定义
2. 跨模块交互：对外暴露打包服务，接收上游传入的音频文件列表，返回打包后的文件结果；缓存未命中时调用其他模块的下载接口获取音频文件；为系统其他模块提供可复用的基础数据、异常规范、接口契约，支撑跨模块交互
3. 第三方依赖：依赖XStream处理XML配置序列化、依赖JNDI实现EJB查找、依赖Guava Cache实现缓存存储、依赖Apache Commons工具类支持LAME文件操作、基于Java EE的EJB/JSF规范实现容器托管
## 架构识别线索
1. 遵循分层架构：Packaging模块内部分为基础支撑层与业务实现层，职责分离清晰
2. 基于Java EE EJB分布式模型设计：同时支持本地/远程服务调用，符合经典Java EE企业应用的部署架构
3. 依赖接口设计：所有业务能力均按本地/远程分离定义接口契约，符合面向接口的组件化设计思想
4. 内置缓存优化：通过Guava Cache实现下载缓存，是典型的性能优化分层设计
5. 配置与代码分离：支持外置XML配置加载、动态生成部署配置，适配EJB部署的需求
