# teammates / Client
## 模块职责
是TEAMMATES项目的客户端侧核心模块，同时承担三大职责：①提供远端Google Cloud Datastore连接管理能力，承载离线数据迁移、数据处理、统计分析、开发测试辅助等运维开发类脚本能力；②作为整个Web应用的入口，负责本地嵌入式Web容器初始化、生命周期管理；③承接前端、后台任务队列发来的所有HTTP请求，完成请求安全处理、路由分发、权限控制、异常统一处理，对接后端业务逻辑并返回JSON响应，是前端交互与后台业务的对接入口。
## 核心功能
1. **远端存储连接与离线数据处理**：封装远端Datastore连接会话管理，提供带分批次扫描、断点续跑、预览模式的通用数据迁移框架，覆盖数据Schema修正、格式转换、脏数据清理、测试数据生成、JSON标准化预处理等多场景脚本能力；针对Datastore查询限制实现分批迭代器，支持按机构增量断点续跑多维度系统用户统计，并支持统计结果本地加密持久化。
2. **Web应用生命周期管理**：提供整个TEAMMATES应用的启动入口，初始化嵌入式Jetty Web容器，完成搜索功能初始化，适配开发环境注册额外调试功能，支持本地开发调试。
3. **Web请求安全处理**：构建多层安全防护链路，包含CSRF校验、请求追踪、安全响应头注入、请求来源校验，区分开发/生产环境适配不同安全规则。
4. **分层Web API能力**：覆盖全场景业务接口：
   - 账户管理：讲师账户创建申请、密钥管理、ID重置、查询删除、注册校验全流程能力；
   - 课程管理：课程增删改查、学生/讲师批量注册更新删除、课程信息获取能力；
   - 反馈会话管理：反馈问题/响应/提交信息查询创建，反馈会话全周期邮件任务调度与执行能力；
   - 通知管理：管理员创建更新系统通知，普通用户标记已读能力；
   - 后台异步任务处理：搜索索引构建、各类业务邮件发送的任务队列回调处理，支持异常重试；
   - 开发辅助：提供开发环境数据导入、错误报告收集等调试能力；
   - 权限控制：基于`Action`继承体系实现分层权限，管理员/讲师/学生/未登录用户按角色做细粒度访问控制，操作前自动校验业务权限。
## 主要代码区域
1. `teammates.client.connector`：远端Datastore连接核心实现，包含抽象基类`DatastoreClient`
2. `teammates.client.scripts`：所有离线工具脚本，含通用/专用数据迁移骨架基类、十余个场景化数据迁移脚本、数据处理/统计/开发辅助类脚本，子包`statistics`存放机构用户统计相关组件
3. `teammates.client.util`：客户端工具类，包含配置加载、进度管理、后端后门直连工具
4. `teammates.main`：Web应用启动入口，负责初始化整个服务
5. `teammates.storage.search`：搜索功能启动初始化组件
6. `teammates.ui.servlets`：Web请求入口与安全处理组件，包含Servlet入口、多层安全过滤器、开发环境特殊适配组件
7. `teammates.ui.webapi`：所有Web API业务实现，按业务功能分为账户、课程、反馈、通知、后台任务等多类独立动作实现类，所有动作继承自抽象`Action`基类遵循统一扩展规范
## 与其他模块的交互
1. 底层依赖：依赖Google Cloud Datastore与Objectify ORM框架完成数据实体操作，依赖Jetty提供嵌入式Web容器，依赖Servlet API处理Web请求，依赖Gson完成JSON序列化
2. 内部模块依赖：
   - 依赖`common`模块的工具类、数据传输对象、存储实体定义完成数据处理
   - 所有业务操作统一对接后端业务逻辑层`logic`完成核心处理
   - 通过`taskQueuer`调度异步任务（搜索索引更新、邮件发送），实现业务与异步逻辑解耦
   - 依赖`emailGenerator`生成业务邮件、`emailSender`完成邮件发送
   - 通过`gateKeeper`完成细粒度访问权限控制
   - 搜索功能依赖搜索服务组件完成索引构建与查询
3. 对接对象：对接前端HTTP请求、后台定时任务、任务队列异步回调请求，处理后返回标准JSON响应；所有离线脚本通过远程连接操作后端Datastore完成数据处理
## 架构识别线索
1. Web API采用**基于继承的单端点单类设计模式**，每个端点对应独立`Action`实现类，通过重写核心方法完成逻辑扩展，基于继承基类实现分层权限控制，框架逻辑与业务逻辑分离清晰
2. 离线脚本采用**骨架基类复用设计**，通用流程（连接管理、分批处理、断点续跑）下沉到抽象基类，具体脚本仅需实现业务迁移逻辑，代码复用度高
3. Web请求采用**过滤器链前置处理模式**，安全校验按固定顺序链路处理，后续再路由到业务Action，符合关注点分离原则
4. 存在明确**环境适配设计**，多处针对开发环境做特殊规则（CORS、安全策略、调试接口）适配，支持本地开发调试
5. 异步任务采用**请求回调解耦模式**，后台任务通过任务队列回调Web API端点执行，实现业务与异步任务解耦
