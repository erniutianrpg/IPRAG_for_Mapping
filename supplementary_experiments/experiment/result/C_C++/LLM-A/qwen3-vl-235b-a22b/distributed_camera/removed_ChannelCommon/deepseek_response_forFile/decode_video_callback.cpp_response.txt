### 4. **Critical Clarification: Where does decoding happen?**
In distributed camera architecture:
- Sink (controlled device): captures raw frames → encodes (e.g., H.264) → sends over SoftBus.
- Source (controller device): receives encoded stream → **decodes** → displays or processes.

Thus, `DecodeVideoCallback` is almost certainly on the **source side**, handling decoded output for consumption — i.e., part of **post-processing** on the source side.

The module `CameraDataPostProcess` explicitly says:

This matches exactly: this callback is the glue between the media decoder and the post-processing logic (`DecodeDataProcess`), enabling the controller to consume remote camera video seamlessly.
