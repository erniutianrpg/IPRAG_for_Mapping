### 2. **What is a QUIC Token Cache?**
In QUIC (especially with TLS 1.3 + Fizz), the client may receive a *retry token* or *resumption token* from the server during handshake. These tokens must be cached persistently (e.g., across process restarts) to enable 0-RTT or fast reconnects. The `QuicTokenCache` interface is part of the QUIC transport layer abstraction.

This class is **not** about DNS resolution, SSL context setup, HTTP parsing, service execution, or high-level server APIs. It is tightly coupled with:
- QUIC transport semantics
- Token handling for connection resumption/retry
- Persistence via file system (via Wangle)
