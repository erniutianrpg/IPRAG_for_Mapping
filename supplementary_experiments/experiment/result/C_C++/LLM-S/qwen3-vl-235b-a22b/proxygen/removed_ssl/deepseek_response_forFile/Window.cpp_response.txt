### 2. **What is a “Window” in Proxygen?**
In HTTP/2 and HTTP/3, **flow control** is implemented via *window sizes*:
- Each stream and the connection has a receive window.
- When a peer sends data, it consumes window; when it receives `WINDOW_UPDATE`, it frees window.
- The `Window` class abstracts this logic: tracking capacity, outstanding bytes, safe arithmetic to avoid overflow/underflow.

This is **core HTTP protocol behavior**, not transport (QUIC handles its own flow control but still relies on HTTP-layer windowing), not DNS, pools, sampling, or services.
