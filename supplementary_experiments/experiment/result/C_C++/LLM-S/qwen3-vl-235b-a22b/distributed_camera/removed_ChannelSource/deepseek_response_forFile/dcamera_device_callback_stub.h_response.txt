Actually, standard pattern in OHOS:
- If Module A wants to receive callbacks from Module B, Module A implements `ICallback`, exposes it as a remote object (`IRemoteObject`), and passes it to Module B.
- Module B then holds a proxy to that callback and invokes methods on it remotely.
- So the **callback receiver** (Module A) must provide a stub (`IRemoteStub<ICallback>`) to handle incoming calls from Module B.

In distributed camera:
- The **source (controller)** wants to receive events from the **sink (device)** — e.g., when a preview frame is ready, or device status changes.
- Therefore, the **source** implements `ICameraDeviceCallback`, creates a stub (`DCameraDeviceCallbackStub`), and registers it with the sink.
- The **sink** then calls methods on that callback (via proxy) to notify the source.

Thus, `DCameraDeviceCallbackStub` is implemented on the **source side**, to receive callbacks *from* the sink.
