- `CameraDataPreProcess`: explicitly for **sink-side preprocessing** — including encoding before transmission.

- The fact that the pipeline is named `DCameraPipelineSink` and only supports `PipelineType::VIDEO` (with encoding node), and validates config ranges, strongly aligns with **preprocessing on the sink side**.

Also, note the inclusion of `encode_data_process.h` — encoding is a classic *pre-transmission* step on the sink.

In distributed camera architecture:
- Sink side: Camera → Preprocess (resize, encode) → Send via Channel
- Source side: Receive → Postprocess (decode, format convert) → Deliver to app

Thus, this file belongs to the **preprocessing stage on the sink side**.
