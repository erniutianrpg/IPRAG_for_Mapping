- `GetInstance()` → singleton pattern for provider.
- `EnableDCameraDevice()`, `DisableDCameraDevice()` → lifecycle control of remote camera devices.
- `AcquireBuffer()`, `ShutterBuffer()` → buffer management (acquire/release frames).
- `OpenSession()`, `CloseSession()` → session lifecycle.
- `ConfigureStreams()`, `ReleaseStreams()`, `StartCapture()`, `StopCapture()` → stream/capture control.
- `UpdateSettings()`, `OnSettingsResult()` → settings negotiation.
- `Notify()` → event notification.
- Helper methods like `GetCallbackBydhBase()`, `GetDCameraDevice()`.

These are **standard camera provider operations**, matching the expected interface of an *HDF provider* that exposes camera capabilities to upper layers (e.g., CameraService or multimedia framework).

Crucially:
- It delegates actual device operations to `DCameraHost::GetInstance()->AddDCameraDevice(...)` etc.
- It does **not** handle:
  - Data transmission (no SoftBus/IPC channel logic),
  - Image preprocessing/postprocessing,
  - Sink/source controller logic,
  - Session/channel establishment at transport level.

Instead, it acts as a **provider proxy** — the HDI-level entry point for camera services.
