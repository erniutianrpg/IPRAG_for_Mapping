### 4. **Critical Clarification: Source vs Sink Processing Direction**

In distributed camera:
- **Sink side** (controlled device): captures raw camera frames → may do *pre-processing* (e.g., crop, encode) before sending.
- **Source side** (controller device): receives encoded stream → does *post-processing* (decode, resize, color convert, frame-rate adjust) to present to local app as if it were local camera.

The class `DCameraPipelineSource`:
- Takes `sourceConfig` (from sink) and `targetConfig` (desired local app config),
- Builds a pipeline to transform data accordingly,
- Has `OnProcessedVideoBuffer` → delivers final processed buffer to listener (likely UI/app),
- Is named `*_source`, and lives in `data_process/pipeline`.

This aligns precisely with **CameraDataPostProcess**.
