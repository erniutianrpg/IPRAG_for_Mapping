### 4. **Critical Differentiator: Pre- vs Post-Process**
- The sink device captures video → processes it (resize, encode, etc.) → sends over channel.
- That processing *before transmission* is **preprocessing** on the sink side.
- `CameraDataPreProcess` is explicitly defined for this role: *"on the sink side or input side, processing image data [...] before it enters the transmission/encoding flow."*
- Although the file uses `EncodeDataProcess`, encoding is a typical step in preprocessing for efficient transmission — especially since JPEG is explicitly rejected (indicating only compressed video streams are supported, implying encoding is required).

Also, note:
- The pipeline is created and managed by `DCameraPipelineSink`, which is clearly a *pipeline orchestrator* for sink-side data flow.
- It does **not** handle IPC, commands, or device control — only data transformation.
- This fits `CameraDataPreProcess` better than `CameraDataProcessCommon`, because:
  - `Common` implies shared abstract interfaces or base classes.
  - This is a concrete implementation specific to sink-side video pipeline with encoding — i.e., *preprocessing*.
