### 4. **Critical Differentiator: Role of `ICameraChannelListener`**

The class holds a `std::shared_ptr<ICameraChannelListener>`. In distributed camera architecture:
- The **source/controller side** (e.g., phone acting as controller) creates a channel to the sink (e.g., IoT camera), and registers a listener to receive:
  - Session open/close events,
  - Received data (preview frames, etc.).
- The **sink side** typically *does not* need a listener for incoming sessions — it listens for connection requests and handles them, but the session object itself is usually owned by the source.

Moreover, the function `OnDataReceived()` is called when data arrives — the listener would then dispatch it upward (e.g., to SourceMgr for preview rendering). This fits **ChannelSource**.

Also, note the file path: `services/channel/` — this matches the expected location for channel implementations, and `ChannelSource` is explicitly defined as the *controller-side channel implementation*.
