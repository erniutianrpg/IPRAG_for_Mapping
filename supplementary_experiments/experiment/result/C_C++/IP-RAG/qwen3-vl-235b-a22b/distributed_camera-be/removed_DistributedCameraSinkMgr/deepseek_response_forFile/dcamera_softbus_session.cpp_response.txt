  - `DCAMERA_SESSION_MODE_JPEG`: JPEG image stream  
  → This shows it handles both **control channel** and **media/data channels**, depending on mode.

#### c. **Directionality**
- The class has:
  - `myDevId_`, `peerDevId_`, `mySessionName_`, `peerSessionName_`

  - It calls `listener_->OnSessionState(...)` on state change.
  - It sends data via `SendBytes/SendStream`, and receives via `OnDataReceived`.

This design is **symmetric**: the same class can be used on *either* side (source or sink), depending on how it’s instantiated and what `mode` and `listener` are passed. However, note:

- In typical usage:

  - On **sink (controlled)** side: accepts session from peer (source), receives control commands, sends video/JPEG.

But the class itself is **agnostic** — it’s a *session handler* that adapts behavior based on mode and listener.
