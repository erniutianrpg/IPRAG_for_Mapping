### 2. **What is a “Window” in HTTP?**
In HTTP/2:
- Each stream and the connection has a flow control window.
- The receiver advertises how many bytes it’s willing to accept (`WINDOW_UPDATE` frames).
- The sender tracks outstanding (sent but unacknowledged) bytes and ensures it doesn’t exceed the window.
- The `Window` class implements this logic: capacity = max allowed, outstanding = bytes sent but not yet acknowledged, `reserve()` = deduct from available window (i.e., send data), `free()` = increase window (i.e., receive `WINDOW_UPDATE`).

The implementation uses signed `int32_t` for `capacity_` and `outstanding_`, with careful overflow/underflow checks — exactly what’s needed for HTTP/2 flow control semantics.
