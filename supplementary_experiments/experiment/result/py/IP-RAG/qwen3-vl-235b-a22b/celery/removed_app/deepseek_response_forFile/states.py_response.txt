### 2. **What is this used for?**
These states are fundamental to Celery’s internal task lifecycle tracking:
- Workers update task state as they process tasks.
- Backends store and retrieve these states.
- Events emit state changes.
- The worker uses them to decide behavior (e.g., whether to retry, propagate exceptions, or mark as ready).
- But crucially: **this file does not implement any backend, worker logic, event handling, or concurrency** — it only *defines* the canonical set of states and their relationships.
