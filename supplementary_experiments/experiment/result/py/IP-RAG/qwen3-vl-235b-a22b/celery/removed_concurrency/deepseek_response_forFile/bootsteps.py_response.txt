### 2. **What is a “Bootstep”?**
In Celery, *bootsteps* are modular, composable components that define parts of the worker startup/shutdown lifecycle. They form a DAG (Directed Acyclic Graph) where dependencies between steps are resolved automatically (e.g., a `ConsumerStep` may require a `ConnectionStep`). This is core to how Celery workers initialize and manage their runtime components (e.g., connections, consumers, heartbeats, control bus).

The `Blueprint` class is the central orchestrator — it holds a set of steps, resolves dependencies, and drives the worker’s lifecycle via `start()`, `close()`, `stop()`, etc.

This is **not** about task execution logic per se, nor configuration loading, nor backends or events — it's about **worker runtime composition**.
