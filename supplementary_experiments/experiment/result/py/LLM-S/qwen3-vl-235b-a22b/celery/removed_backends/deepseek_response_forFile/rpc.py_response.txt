### 2. **What is a Result Backend?**
In Celery architecture:
- A **result backend** is responsible for storing and retrieving task results (e.g., success/failure, return value, traceback).
- It is *not* part of the worker execution logic per se, but a supporting infrastructure component used by both workers (to store results) and clients (to retrieve them).
- Backends are pluggable and live under `celery.backends.*` (e.g., `celery.backends.rpc`, `celery.backends.redis`, `celery.backends.database`, etc.).

While the worker module (`worker`) *uses* backends, the backend implementations themselves are **separate**, typically grouped under a dedicated namespace like `backends`, which is *not listed* among the candidate modules.
