### 2. **What is a Result Backend?**
In Celery architecture:
- A **result backend** stores task return values, states, and metadata (e.g., success/failure, traceback).
- It is *not* part of the core app logic (`app`), worker runtime (`worker`), or concurrency pool (`concurrency`).
- It is an *extension point* that integrates with the core but is implemented separately.
- Celery provides built-in backends (e.g., Redis, RPC, database, MongoDB), and they live in dedicated modules.
