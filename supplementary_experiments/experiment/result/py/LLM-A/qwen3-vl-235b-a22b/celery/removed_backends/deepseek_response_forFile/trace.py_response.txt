### 4. **Where does task execution tracing belong?**
In Celery architecture:
- The **worker** module is responsible for consuming tasks, executing them, managing requests, and maintaining state.
- Tracing task execution — especially the logic that runs *during* task execution (e.g., catching exceptions, logging, calling errbacks, updating result backend) — is part of the **worker’s runtime execution strategy**, not the app-level configuration or external tooling.

Specifically:
- `trace_task` and `fast_trace_task` are called by the worker when a task request is received and needs to be executed.
- `TraceInfo` is used to manage the outcome of a task run and trigger appropriate side effects (logging, callbacks, state updates).
- `setup_worker_optimizations`, `reset_worker_optimizations`, `_install_stack_protection()` indicate worker-specific optimizations and protections — further tying this to the **worker** runtime.

Also, note:
