### What is a *backend* in Celery?
In Celery, **backends** (specifically *result backends*) are responsible for storing and retrieving task results. They are pluggable components that implement interfaces like `get()`, `set()`, etc., and are configured via `result_backend` setting.

Backends are **not** part of core application logic (`app`), worker runtime (`worker`), concurrency pools (`concurrency`), CLI (`bin`), events (`events`), security (`security`), loaders (`loaders`), fixups (`fixups`), or utils (`utils`) — though they may *use* utilities.

However, in Celery’s module organization:
- Official backend implementations (e.g., `celery.backends.redis`, `celery.backends.database`, `celery.backends.mongodb`, etc.) live under the `celery.backends` package.
- The `contrib` module is described as: *"contains Celery extension and helper functionality, including [...] broker migration, pytest test support, [...] and test worker/app capabilities."*
